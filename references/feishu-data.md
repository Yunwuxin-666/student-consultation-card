# 飞书读取与案例数据

运行前复制仓库根目录的 `config.example.json` 为 `config.json`，填写自己的 Base token、表 ID 和产品页面。`config.json` 不应提交到公开仓库。

## CLI和会议

使用已登录的 `lark-cli` 和 `--as user`。从妙记链接提取 token 后读取完整逐字稿：

```powershell
lark-cli minutes +detail --minute-tokens '<minute-token>' --transcript --as user
```

按返回的 `data.minutes[].artifacts.transcript_file` 读取全文。日期来自会议资料，不能用当前日期替代。AI 摘要只能辅助定位，结论需核对原始发言。

## 学员 Base

从 `config.json` 读取 `base_token`、`consultation_table_id`、`student_table_id`、`review_table_id`。不要把真实 ID 写入交付文档或公开仓库。先用咨询表匹配当前学员，再从营课学员表和评价表交叉核对案例。

常用字段：`真实姓名`、`专业`、`学历`、`年龄`、`学校`、`工作年限`、`商品名称（内部下单）`、`求职招聘类型`、`处于转行的什么阶段`、`你找到实习/正职Offer的岗位名称（可多选）`、`转行后最终去向实习/正职Offer的公司`、`拿到的实习Offer薪酬水平（日薪）：`、`转行后拿到的Offer薪酬水平（月薪base，年薪/月份，可多选）：`。

字段变化时先用 `base +field-list`。姓名搜索只用于定位学员，不能据此写完个人画像。定位后按需读取求职阶段、毕业时间、工作状态与年限、当前工作内容、项目或作品、已掌握工具、意向岗位与城市、学习时间、预算及顾虑字段；缺失细节回逐字稿核对，不能把旧表值混成咨询当天现状。外发文档只写与方向、行动和方案相关的信息，不带联系方式或内部备注。案例优先云端过滤，避免只读首屏。营课表与评价表按姓名和背景交叉匹配，检查分页与重复记录。

## 阶段匹配

先用 `求职招聘类型`、年级、工作年限判断校招或社招，并核对评价表的实际结果。在校学员优先校招案例；有证据时同时呈现实习 Offer 和校招正职 Offer。随后比较专业、学历、年龄、岗位、学校类型。不得把社招正职案例写成校招结果。校招实习案例按实习日薪呈现，校招正职案例按月薪呈现；无前薪时不计算涨幅。

## 薪资与隐私

保持原始区间，区分日薪、月薪、税前/税后、实习/正式、全部 Offer/最终去向。多份 Offer 不得把最高薪资错误绑定最终公司。姓名脱敏；不输出联系方式、内部记录 ID 或私人链接。不能从培训经历推断录用因果。
