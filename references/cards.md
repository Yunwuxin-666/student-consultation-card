# 三张标准图：职业规划画布、学习行动卡、往期案例卡

三图是七模块文档的视觉摘要。顺序与图位固定：第1节咨询信息后是职业规划画布，第5节行动正文后是学习行动卡，第7节案例正文后是往期案例卡。保留旁边文字正文，卡片不用表格、转化解读或泛泛口号。如果本地还安装有咨询案例匹配和项目管理技能，可借鉴其判断方法；本技能自身的阶段匹配与行动规则必须完整执行。

## 职业规划画布

用精益画布的九模块逻辑重组同一份诊断文档，标题固定为“职业规划画布”。九格要回答读者实际会问的问题：①现在遇到什么具体问题；②建议怎么解决；③已有能力怎样用于新方向；④做过哪些相关工作或项目；⑤先看什么岗位；⑥用什么结果判断进展；⑦到哪里找机会；⑧需要投入什么时间或支持；⑨接下来要得到什么可核实的结果。模块标题可用通俗写法，如“目前问题”“已有能力怎么用”“如何看进展”，不必强行使用“独特价值”“关键指标”“预期验证”等术语。

先把第1节个人画像写完整，再制作画布。副标题交代阶段、当前状态和目标；九格中的经历、城市、岗位、作品及课程应能在正文找到对应事实。每格通常写2个信息点或1—2句完整话，能独立读懂“谁做什么、为了解决什么”，不只放“项目验证方向”“作品集与求职衔接”一类名词短语。避免重复同一段背景；每格承担不同作用。画布是可读的总览，不是把正文逐句截短。

在固定画幅内优先精简次要内容或拆短长句，保持信息完整；不要用斜杠、竖线、缩写、字号过小或截断句子来塞字。可写“制作一组品牌海报和短视频，展示从需求到成品的过程”，少写“跑通内容生产链路”。独特价值只能归纳已有能力与目标工作的连接，不能写成未经证实的雇主认可、竞争优势或承诺。没有收入数据时不写薪资目标；未提及的产品和价格不加入画布。

画布为2000×1125横版，用三列三行瑞士网格承载九个模块。黄、白、黑是唯一主色：白底、黑色分隔线、少量黄色编号与目标岗位强调。左上角小色块和英文栏目标记借鉴 Figma 标注语言，但不使用紫色选框、回形针、纸张纹理、倾斜便签或阴影。修改文案时逐格查看：标题与标签不相撞，句子没有被裁切，字体不用缩到难读；信息放不下时重新组织句子，而非只保留关键词。

## 案例卡

用咨询.skill从当前学员的求职阶段、专业、学历、年龄、学校类型和岗位目标分层匹配案例。先保证校招或社招阶段一致；在校学员有可核实案例时，卡面同时放实习Offer与校招正职Offer。再看同专业和相邻专业；课程、岗位、结果、薪资要从营课学员表与评价表核实。通常精选两例，同等相关时优先证据更全者。卡面只写脱敏称呼、背景、课程、岗位、去向和有记录的薪资。校招实习案例使用实习日薪，不套用正式Offer月薪与涨幅结构；缺失转行前薪资时不显示涨幅。没有明确证据的项留空或改选案例，不写评价、推断或“该案例证明”。多份Offer不能把最高一份和最终去向错误绑定。

## 学习行动卡

用项目管理.skill把导师在咨询中的方向建议和相关课程内容整合为可执行的阶段。每阶段有实际动作及可检查的产出；先基础与方向，再项目与作品，再求职与调整，只有本次材料支持时才这样排列。课程阶段和求职阶段可并行时按实际情况表达，不机械加周数、作品数、导师责任或保证结果。若导师明确说需要视频能力，而学员偏好静态图像，卡面保留“先图像，补视频”的实际建议。

## 生成与查看

填写 UTF-8 JSON。`canvas` 对象包含 `tag`、`subtitle`、9 个 `blocks`（每项 `heading` 和 `lines` 数组）、`source_note`、`footer_phrase`；可选 `eyebrow` 与 `title`。行内用 `**文字**` 标重点。`action` 和 `cases` 对象沿用现有渲染器字段。三个对象可放在同一个 JSON 中，以下两条命令共用它：

```powershell
python -X utf8 ./scripts/render_canvas.py --input ./outputs/<学员>_三图数据.json --output-dir ./outputs --slug <slug>
python -X utf8 ./scripts/render_cards.py --input ./outputs/<学员>_三图数据.json --output-dir ./outputs --slug <slug>
```

脚本用 Chrome 或 Edge 将 HTML 渲染成三张 PNG，并保留 HTML 供修改。三张图统一使用黄白黑配色、瑞士网格和克制的 Figma 式编号标注。排版以对齐、留白与细线分区建立层级；黄色只强调编号、阶段产出或关键结果，不铺满大面积装饰。中文由 HTML 排版，避免图片生成造成文字错误。不要回退到拼贴纸张、营销海报、蓝色后台看板或渐变信息卡。

用本地图片查看工具逐张检查文字、折行、项目顺序、薪资标签和空间，必要时缩短文案再渲染。绝不因排版改动事实。运行环境需有 Python 与 Chrome/Edge，无需 Pillow。

## 嵌入飞书

发布 Markdown 后，依次读取第1、5、7节 `docs +fetch --scope section --detail with-ids`。在第1节最后一个咨询信息正文块后插入画布；第5节行动正文后插入行动卡；第7节案例正文后插入案例卡。若有明确占位段落，用 `docs +update --command block_replace --block-id <占位ID> --content '<img path="@./outputs/xxx.png" width="760"/>'` 替换；否则用 `block_insert_after`。三次写入依次执行，每次按最新 fetch 的 ID 操作；已有图时替换对应图块，避免重复。不要用 `docs +media-insert` 将图片堆在文末。

最后回读三个章节，确认图片都在对应文字之后，正文未被误删，且顺序与示例文档一致。可在本地 Markdown 相应章节加入 PNG 相对路径；云文档中的图片以回读 `img` 块为准。
